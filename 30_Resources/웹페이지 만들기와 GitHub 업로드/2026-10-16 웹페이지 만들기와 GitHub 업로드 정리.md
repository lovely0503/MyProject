# 웹페이지 만들기와 GitHub 업로드 정리

2026-10-16에 옵시디언 노트를 GitHub 저장소에 올리고, 잡코리아 QA 공고 노트를 웹페이지로 바꿔 다시 올렸다. 그 과정과 쓰인 기술을 정리했다.

- 저장소: https://github.com/lovely0503/MyProject
- 만든 웹페이지: `00_Inbox/2026-10-16-jobkorea-qa.html`
- 원본 노트: [[2026-10-16 잡코리아 QA엔지니어 공고]]

## 전체 흐름

```text
마크다운 노트 ──(내용을 데이터로 옮김)──▶ HTML 파일 ──(git commit)──▶ 내 컴퓨터 저장소 ──(git push)──▶ GitHub
```

1. 올릴 파일을 고르고 민감한 정보가 없는지 확인한다.
2. GitHub에 로그인한다. (`gh auth login`)
3. 저장소를 내 컴퓨터로 받는다. (`git clone`)
4. 파일을 복사하고 기록을 남긴다. (`git add`, `git commit`)
5. GitHub로 보낸다. (`git push`)
6. GitHub에서 파일이 올라갔는지 확인한다.

## 1부. 마크다운을 웹페이지로 바꾸기

### 웹페이지를 이루는 세 가지

| 기술 | 역할 | 비유 |
| --- | --- | --- |
| **HTML** | 내용과 구조 (제목, 문단, 목록, 버튼) | 집의 뼈대 |
| **CSS** | 모양 (색, 글꼴, 간격, 배치) | 인테리어 |
| **JavaScript** | 동작 (필터 버튼, D-day 계산, 체크 저장) | 전기와 스위치 |

세 가지를 모두 파일 **하나**(`.html`)에 넣었다. 파일 하나만 있으면 어디서든 열리기 때문이다.

### HTML 기본 뼈대

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">                                                 <!-- 한글이 깨지지 않게 -->
  <meta name="viewport" content="width=device-width, initial-scale=1">  <!-- 휴대폰 화면에 맞게 -->
  <title>잡코리아 QA 공고</title>                                         <!-- 브라우저 탭 이름 -->
  <style> /* CSS가 들어가는 곳 */ </style>
</head>
<body>
  <!-- 화면에 보이는 내용 -->
  <script> // JavaScript가 들어가는 곳 </script>
</body>
</html>
```

### 마크다운 문법과 HTML 태그 대응

| 마크다운 | HTML | 이번 페이지에서 쓴 곳 |
| --- | --- | --- |
| `# 제목` | `<h1>` | 페이지 제목 |
| `## 소제목` | `<h2>` | 주의할 점, 다음에 할 것 |
| `- 항목` | `<ul><li>` | 주의할 점 목록 |
| `**굵게**` | `<strong>` | 강조한 숫자와 문장 |
| `[글](주소)` | `<a href="주소">` | 공고 원문 보기 버튼 |
| `- [ ] 할 일` | `<input type="checkbox">` | 다음에 할 것 체크리스트 |
| 표 | 카드(`<article>`) | 표 대신 공고마다 카드 하나 |

> 표는 화면이 좁으면 옆으로 잘린다. 그래서 휴대폰에서도 보기 쉽게 **카드** 형식으로 바꿨다.

### CSS에서 쓴 기술

**1) 색을 변수로 모아 두기**

```css
:root {
  --bg: #f4f6f8;      /* 배경색 */
  --fg: #17202a;      /* 글자색 */
  --accent: #1f5f8b;  /* 강조색 */
}
body { background: var(--bg); color: var(--fg); }
```

색을 한곳에 모아 두면 나중에 한 줄만 고쳐도 전체 색이 바뀐다.

**2) 다크 모드**

```css
@media (prefers-color-scheme: dark) {
  :root { --bg: #12171c; --fg: #e6ebf0; }
}
```

컴퓨터나 휴대폰이 다크 모드이면 변수 값만 바꿔서 어두운 화면이 된다.

**3) 그리드(grid)로 칸 나누기**

```css
.cards { display: grid; grid-template-columns: repeat(2, 1fr); gap: 12px; }
```

카드를 2칸으로 나란히 놓는다. `1fr`은 남은 공간을 똑같이 나눈다는 뜻이다.

**4) 반응형 (화면 크기에 맞추기)**

```css
@media (max-width: 720px) {
  .cards { grid-template-columns: 1fr; }  /* 휴대폰에서는 1칸 */
}
```

화면 폭이 720px보다 좁으면 카드를 한 줄에 하나씩 보여 준다.

### JavaScript에서 쓴 기술

**1) 데이터와 화면 나누기**

공고 내용을 표로 직접 쓰지 않고 **배열**에 데이터로 담았다.

```js
const JOBS = [
  { type: "new", company: "마카롱팩토리", title: "QA엔지니어 (전환형 인턴)", deadline: "2026-12-10" },
  { type: "exp", company: "미리디", title: "[미리캔버스] QA 엔지니어", deadline: "2026-10-26" },
  // ...
];
```

공고가 늘어나면 이 목록에 한 줄만 추가하면 된다. 카드 모양은 함수 하나(`card`)가 똑같이 만들어 준다.

**2) 필터 버튼**

```js
const list = JOBS.filter(j => filter === "all" || j.type === filter);
```

`filter`는 조건에 맞는 것만 골라내는 기능이다. "신입 가능"을 누르면 `type`이 `"new"`인 공고만 남는다.

**3) D-day 계산**

```js
const diff = Math.round((new Date(마감일) - 오늘) / 86400000);
```

두 날짜를 빼면 밀리초(1/1000초) 단위의 차이가 나온다. 하루는 86,400,000밀리초이므로 그 값으로 나누면 남은 일수가 된다. 페이지를 열 때마다 다시 계산해서 날짜가 지나도 맞는 값이 나온다.

**4) 체크 상태 저장 (localStorage)**

```js
localStorage.setItem("jobkorea-qa-t1", "1");  // 저장
localStorage.getItem("jobkorea-qa-t1");       // 불러오기
```

브라우저 안의 작은 저장 공간이다. 새로고침해도 체크가 남아 있다. 단, **그 브라우저에만** 저장되어 다른 컴퓨터에서는 보이지 않는다.

## 2부. GitHub에 올리기

### 용어 정리

| 용어 | 뜻 |
| --- | --- |
| **Git** | 파일이 바뀐 기록을 남기는 프로그램 (내 컴퓨터에서 동작) |
| **GitHub** | Git 기록을 인터넷에 올려 두는 사이트 |
| **저장소 (repository)** | 프로젝트 폴더 하나. 이번에는 `MyProject` |
| **clone** | GitHub 저장소를 내 컴퓨터로 복사해 오기 |
| **commit** | "지금 상태를 저장"하고 메모를 남기기 (게임의 세이브) |
| **push** | 내 컴퓨터의 commit을 GitHub로 보내기 |
| **pull** | GitHub의 새 변경 사항을 내 컴퓨터로 가져오기 |
| **main** | 저장소의 기본 브랜치 이름 |
| **gh** | GitHub를 터미널에서 다루는 프로그램 (GitHub CLI) |

### 단계별 명령어

**1) GitHub 로그인** — 처음 한 번만

```bash
gh auth login
```

- GitHub.com → HTTPS → Yes → Login with a web browser 순서로 고른다.
- 터미널에 나온 **8자리 코드**를 브라우저에 입력하고 Authorize를 누른다.
- `Logged in as lovely0503`가 나오면 끝.

> 브라우저에서 github.com에 로그인한 것과 **git 로그인은 따로**다. 이번에 처음 push가 멈춘 이유가 이것이었다.

**2) 저장소 받기**

```bash
git clone https://github.com/lovely0503/MyProject
```

**3) 파일 넣고 기록 남기기**

```bash
git add 00_Inbox/2026-10-16-jobkorea-qa.html
git commit -m "Add JobKorea QA engineer postings web page"
```

- `add`: 이번 commit에 넣을 파일을 고른다.
- `commit -m "메모"`: 무엇을 바꿨는지 메모와 함께 저장한다.

**4) GitHub로 보내기**

```bash
git push origin main
```

`origin`은 GitHub 저장소, `main`은 브랜치 이름이다.

**5) 확인**

```bash
git status       # 아직 commit하지 않은 파일이 있는지
git log --oneline  # commit 기록 보기
```

GitHub 사이트에서 새로고침(F5)해서 파일이 보이는지도 확인한다.

### 기존 파일을 지우지 않는 방법

- 저장소를 먼저 `clone`해서 **원래 있던 파일을 확인**했다. (`README.md`, `mypage`)
- 올릴 파일 이름이 기존 파일과 **겹치지 않는지** 확인했다.
- 파일을 **추가만** 했다. 수정하거나 지운 파일이 없으면 기존 파일은 그대로 남는다.
- 두 번째 업로드 전에는 `git pull`로 GitHub의 최신 상태를 먼저 받았다.

### 공개 저장소에 올리기 전 확인할 것

- [ ] 비밀번호, API 키, 토큰이 없는가
- [ ] 전화번호, 주소, 학번 같은 개인정보가 없는가
- [ ] 공개돼도 괜찮은 내용인가 (예: 구직 중이라는 사실)
- [ ] 설정 파일(`.obsidian`)이나 중복 파일(`index.zip`)처럼 올릴 필요 없는 파일을 뺐는가

> 한 번 공개로 올린 파일은 지워도 commit 기록에 남는다. **올리기 전에** 확인하는 것이 중요하다.

## 3부. 웹사이트로 보이게 하기 (GitHub Pages)

GitHub에서 `.html` 파일을 열면 웹페이지가 아니라 **코드**가 보인다. 웹사이트처럼 보려면 **GitHub Pages**를 켜야 한다.

- 켜는 곳: 저장소 → **Settings** → **Pages** → Branch를 `main`으로 고르고 Save
- 몇 분 뒤 주소가 생긴다.
  `https://lovely0503.github.io/MyProject/00_Inbox/2026-10-16-jobkorea-qa.html`
- 주의: 켜면 저장소의 **다른 html 파일도 모두** 웹에서 열린다.

(2026-10-16 기준 아직 켜지 않았다.)

## 이번에 겪은 문제와 해결

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| push가 끝나지 않고 멈춤 | git이 로그인 창을 띄우고 기다림 | `gh auth login`으로 터미널에서 로그인 |
| GitHub에 폴더가 안 보임 | push가 실패해서 실제로 안 올라감 | 로그인 후 다시 push |
| html이 코드로 보임 | GitHub은 html을 화면으로 그려 주지 않음 | GitHub Pages 사용 |
| 한글 파일 이름이 `\354\233...`로 보임 | git이 한글을 숫자로 바꿔 보여 줌 | `git config core.quotepath false` |
