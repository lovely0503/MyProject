# 모바일인덱스에서 만난 MCP 이해하기

> MCP는 AI가 외부 서비스의 데이터와 기능을 사용할 수 있도록 연결하는 공통 통신 규칙이다. 모바일인덱스 MCP는 이 규칙을 이용해 앱 분석 데이터를 AI와 연결한다.

## AI가 외부 데이터를 쓰려면 연결이 필요하다

AI에게 “이 앱을 지난달에 몇 명이 이용했어?”라고 물었다고 생각해 보자. 모델이 학습하면서 익힌 지식만으로는 특정 서비스의 최근 통계나 내 계정으로만 볼 수 있는 자료를 정확히 알기 어렵다. 필요한 데이터를 실제로 조회할 수 있는 통로가 있어야 한다.

**MCP는 Model Context Protocol의 약자**다. AI 애플리케이션과 외부 데이터·도구 사이의 연결 방식을 표준화한다. 공식 문서는 여러 기기를 같은 규격으로 연결하는 USB-C에 비유한다. 여기서 중요한 것은 물리적인 케이블이 아니라, 서로 다른 프로그램이 같은 방식으로 기능을 주고받는다는 점이다. [MCP 공식 소개](https://modelcontextprotocol.io/docs/2026-07-28/getting-started/intro)

예를 들어 어떤 서비스가 MCP 서버를 제공하면, 이를 지원하는 AI 애플리케이션은 서버가 어떤 기능을 제공하는지 확인하고 필요한 기능을 호출할 수 있다. 다만 지원 기능, 인증 방식, 사용 권한이 맞아야 실제 연결이 가능하다.

## 모바일인덱스에서는 무엇을 연결할까?

모바일인덱스 MCP는 모바일인덱스가 제공하는 **앱 분석 데이터를 자연어로 조회하고 분석하도록 연결하는 서비스**다. 사용자가 웹사이트의 여러 메뉴를 직접 찾아다니는 대신, 연결된 AI에 질문하면 필요한 데이터 조회와 설명을 한 흐름으로 진행할 수 있다. 공식 소개에는 앱 사용자 규모, 사용시간, 이탈·유지, 사용자 구성 등의 분석 사례가 안내되어 있다. [모바일인덱스 MCP 소개](https://www.mobileindex.com/home/mcp/usage/mi-mcp-intro)

다음은 이해를 위한 질문 예시이며, 실제 조회 결과는 아니다.

- “조회 가능한 가장 최근 월을 확인하고, 배달 앱 세 개의 MAU를 비교해 줘.”
- “선택한 게임 앱의 최근 3개월 사용자 수와 사용시간 변화를 정리해 줘.”
- “조회 기간과 출처를 함께 적고, 데이터로 확인되는 사실과 해석을 나눠 설명해 줘.”

**MAU는 Monthly Active Users, 즉 월간 활성 사용자 수**를 뜻한다. 모바일인덱스 데이터 가이드에서는 선택 기간 동안 앱을 한 번 이상 실행한 사용자 수를 설명하며 DAU·WAU·MAU를 구분한다. 같은 숫자를 비교하더라도 기간과 지표 정의가 같아야 의미가 있다. [모바일인덱스 데이터 가이드](https://www.mobileindex.com/home/mi-data)

모바일인덱스의 공식 활용 가이드에는 경쟁 앱 비교, 이용자 특성별 순위, 반복 보고서 작성 사례도 있다. 안내 화면의 수치는 예시일 수 있으며, 실제 조회 가능한 데이터와 기간은 이용 중인 권한·플랜에 따라 달라진다. **조회할 때마다 현재 공개된 데이터를 요청하는 것과, 모든 지표가 지금 이 순간의 실시간 값인 것은 구분해야 한다.** [모바일인덱스 활용 가이드](https://mcp-guide.mobileindex.com/guide)

## 질문 한 번이 처리되는 흐름

다음은 개념을 이해하기 위한 흐름이다. 실제 구현은 사용하는 앱과 서버에 따라 달라진다.

```text
사용자가 AI에 질문
    → AI 애플리케이션이 사용할 수 있는 MCP 기능 확인
    → 필요한 조회 기능 호출
    → 모바일인덱스 서비스에서 권한 범위의 데이터 조회
    → 결과를 AI 애플리케이션에 전달
    → AI가 표·요약·설명으로 정리
```

이때 역할을 나누면 다음과 같다.

| 용어 | 역할 | 이해를 위한 예 |
| --- | --- | --- |
| 호스트(Host) | 사용자가 대화하고 작업하는 AI 애플리케이션 | MCP 연결을 지원하는 AI 앱이나 개발 도구 |
| 클라이언트(Client) | 호스트 안에서 MCP 서버와 통신하는 구성요소 | 요청을 보내고 결과를 받는 연결 담당 |
| 서버(Server) | 외부 데이터나 기능을 MCP 방식으로 제공하는 프로그램 | 앱 분석 조회 기능을 제공하는 MCP 서버 |

여기서 서버는 꼭 별도의 대형 컴퓨터를 뜻하지 않는다. 내 PC에서 실행하는 프로그램일 수도 있고, 외부 서비스가 운영하는 원격 프로그램일 수도 있다. [MCP 공식 아키텍처](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/learn/architecture.mdx)

## MCP가 제공하는 도구·자료·프롬프트

MCP 서버는 다음과 같은 종류의 기능을 제공할 수 있다. 모든 서버가 세 가지를 모두 제공해야 하는 것은 아니다.

| 구분 | 쉽게 이해하면 | 예시 |
| --- | --- | --- |
| 도구(Tools) | 실행할 수 있는 기능 | 앱 지표 조회, 검색, 계산 |
| 자료(Resources) | 문맥으로 불러올 수 있는 데이터 | 파일 내용, 참고 문서 |
| 프롬프트(Prompts) | 사용자가 골라 쓸 수 있는 재사용 요청 양식 | 일정한 형식의 분석 요청 템플릿 |

이 표의 예시는 일반적인 개념 설명이며, 모바일인덱스가 각각을 모두 지원한다는 의미는 아니다. [MCP 공식 아키텍처](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/learn/architecture.mdx)

## API·크론잡·작업 규칙과는 무엇이 다를까?

이전에 만든 GitHub 업로드와 텔레그램 알림을 떠올리면 차이를 이해하기 쉽다.

| 개념 | 맡는 역할 | 내 작업에 연결해 보면 |
| --- | --- | --- |
| API | 프로그램이 다른 서비스의 기능을 요청하는 창구 | 스크립트가 GitHub에 파일을 올리거나 Telegram에 메시지를 요청 |
| MCP | AI 앱과 외부 기능 사이의 공통 연결 규칙 | AI가 사용할 도구를 발견하고 정해진 형식으로 호출하도록 연결 |
| 크론잡·작업 스케줄러 | 정해진 시간에 작업 실행 | 매시간 업로드 스크립트를 실행 |
| 작업 규칙·스킬 문서 | 일을 어떤 기준과 순서로 할지 안내 | 날짜 형식, 분석 순서, 보고서 작성 기준을 지정 |

API와 MCP는 함께 사용할 수 있다. MCP 서버가 AI의 요청을 받고, 내부에서 기존 서비스 API를 호출하는 구조가 가능하다. MCP 서버를 제공한다고 해서 기존 API가 사라지는 것은 아니다.

내가 구성한 매시간 GitHub 업로드는 **Windows 작업 스케줄러와 PowerShell 스크립트가 API를 호출하는 방식**이었다. 이것만으로 MCP를 사용했다고 말할 수는 없다. 또한 MCP를 연결하는 것만으로 정기 실행이 자동 설정되지는 않는다. 예약 실행, 데이터 조회, 메시지 전송은 각각 필요한 기능과 권한을 갖춰 연결해야 한다.

모바일인덱스도 분석 방법을 안내하는 스킬 파일과 데이터를 조회하는 MCP 연결을 구분해 설명한다. 스킬은 “어떻게 분석할까”에 가깝고, MCP 연결은 “어떤 데이터를 조회할 수 있을까”와 관련된다. [모바일인덱스 MCP 소개](https://www.mobileindex.com/home/mcp/usage/mi-mcp-intro)

## 사용할 때 확인할 점

1. **권한과 범위:** 어떤 계정으로 연결했고 어떤 데이터까지 조회할 수 있는지 확인한다.
2. **조회 조건:** 앱, 기준 월, 비교 기간, 지표 정의, 단위를 결과에 남긴다.
3. **사실과 해석:** 사용자 수 감소라는 관측값과 그 원인에 대한 추정을 나누어 읽는다. 데이터를 연결해도 AI 해석이 항상 맞는 것은 아니다.
4. **인증정보:** 키나 토큰을 공개 마크다운, GitHub 파일, 공유 대화에 적지 않는다.
5. **현재 안내:** 지원 플랫폼과 연결 방법, 요금·권한 조건은 바뀔 수 있으므로 서비스의 최신 공식 가이드를 확인한다.
