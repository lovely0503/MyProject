# 마크다운 가이드 정리

출처: [마크다운 사용법 완벽 가이드 — 유한대학교 컴퓨터공학과 게임콘텐츠전공](https://game-contents.vercel.app/mentoring/05.markdown_gaide.html)

원문의 16개 주제를 학습용으로 요약했다. 예제는 복사해서 연습하기 좋게 재구성했다.

## 01. 마크다운이란?

일반 텍스트에 기호를 붙여 문서 구조와 서식을 표현하는 방식이다. `.md` 파일로 저장하며 노트, README, 개발 문서 등에 활용한다. 원문 자체도 읽기 쉽고 여러 편집기에서 열 수 있지만, 확장 문법의 지원 범위는 앱마다 다르다.

## 02. 제목

`#` 뒤에 공백을 넣는다. 개수에 따라 1~6단계로 구분한다.

```markdown
# 학습 노트
## 오늘의 주제
### 핵심 개념
#### 세부 설명
##### 참고 사항
###### 보충 메모
```

밑줄 형태도 가능하다. 제목 아래 `===`는 1단계, `---`는 2단계 제목을 만든다.

## 03. 텍스트 강조

| 용도 | 입력 예시 |
| --- | --- |
| 굵게 | `**핵심**` 또는 `__핵심__` |
| 기울임 | `*강조*` 또는 `_강조_` |
| 굵게와 기울임 | `***매우 중요***` |
| 취소선 | `~~이전 내용~~` |
| 인라인 코드 | `` `score` `` |

파일명이나 명령어는 인라인 코드로 감싸면 기호를 그대로 보여주기 좋다.

## 04. 단락과 줄바꿈

- **새 문단:** 문장 사이에 빈 줄을 넣는다.
- **같은 문단의 줄바꿈:** 줄 끝에 공백 두 개를 넣고 Enter를 누른다.
- 단순 Enter의 표시 방식은 편집기 설정에 따라 달라질 수 있다.

```markdown
첫 번째 문단입니다.

두 번째 문단입니다.
```

## 05. 목록

순서 없는 목록은 `-`, `*`, `+`로 시작한다. 순서 있는 목록은 숫자와 마침표를 사용한다. 하위 항목은 들여쓴다.

```markdown
- 게임 제작
    - 기획
    - 개발

1. 아이디어 정리
2. 시제품 제작
3. 플레이 테스트
```

순서 목록에 `1.`을 반복 입력해도 렌더링 시 연속된 번호로 표시할 수 있다.

## 06. 링크

```markdown
[수업 자료](https://example.com)
[수업 자료](https://example.com "자료 열기")

<https://example.com>
<student@example.com>

[강의 노트][class]

[class]: https://example.com
```

참조 링크는 주소를 별도 줄에 모아 관리하는 방식이다.

## 07. 이미지

링크 앞에 `!`를 붙인다. 대체 텍스트에는 이미지가 전달하는 내용을 적는다.

```markdown
![플레이 화면](play.png)
![플레이 화면](play.png "테스트 장면")
[![자료 배너](banner.png)](https://example.com)

![플레이 화면][shot]

[shot]: play.png
```

옵시디언에서는 다음처럼 너비를 지정할 수 있다.

```markdown
![[play.png|300]]
```

예제의 이미지 이름은 실제 보관함에 있는 파일 이름으로 바꿔야 한다.

## 08. 인용문

`>`로 시작하고, 중첩할 때는 기호를 추가한다. 인용문 안에서도 강조와 코드를 사용할 수 있다.

```markdown
> 오늘의 학습 메모
>
> **핵심:** 작은 예제로 먼저 연습한다.
>> 추가로 확인할 내용
```

## 09. 수평선

`---`, `***`, `___`를 단독 줄에 작성한다. 앞뒤에 빈 줄을 두면 제목 문법과 혼동하기 어렵다.

```markdown
첫 번째 내용

---

두 번째 내용
```

기호 뒤에 설명 문장을 붙이면 수평선으로 인식되지 않을 수 있다.

## 10. 코드

짧은 코드는 백틱 한 쌍, 여러 줄은 백틱 세 개로 감싼다. 코드 자체에 백틱이 있으면 바깥쪽 백틱 개수를 늘린다.

````markdown
변수 `score`에 점수를 저장한다.

```python
score = 80
print(score)
```

백틱 표시 예시: `` `score` ``
````

여는 코드 울타리 뒤에 `python`, `javascript`, `csharp`, `html`, `json` 등의 언어 이름을 붙이면 해당 언어의 구문 강조에 활용된다. 공백 네 칸 들여쓰기로도 코드 블록을 만들 수 있다.

## 11. 표

열은 `|`로 나누고, 제목 행 아래에 구분 행을 둔다. 구분 행의 `:` 위치로 정렬을 지정한다.

```markdown
| 작업 | 담당 | 진행률 |
| :--- | :---: | ---: |
| 기획 | 지민 | 100% |
| 개발 | 수현 | 60% |
```

- `:---`: 왼쪽 정렬
- `:---:`: 가운데 정렬
- `---:`: 오른쪽 정렬

셀 안에는 강조, 링크, 인라인 코드를 넣을 수 있다. 여러 줄 코드 블록은 표 밖에 두는 편이 좋다.

## 12. 체크박스

`- [ ]`는 미완료, `- [x]`는 완료를 나타낸다. 대괄호 안과 뒤의 공백에 주의한다.

```markdown
- [x] 학습 자료 읽기
- [ ] 실습 진행
    - [ ] 표 작성
    - [ ] 이미지 삽입
```

## 13. 이스케이프

문법 기호를 글자로 표시하려면 앞에 역슬래시 `\`를 붙인다.

```markdown
\*강조가 아닌 별표\*
\# 제목이 아닌 문장
\[대괄호 표시\]
1\. 번호 목록이 아닌 문장
```

기호가 많은 파일명이나 코드는 백틱으로 감싸는 방법도 편리하다.

## 14. 확장 기능

원문에서 GitHub 확장 항목으로 소개한 기능이다. 표·체크박스 같은 GFM 문법과 각 서비스에서 추가로 제공하는 기능은 구분해서 이해하면 좋다.

### 각주

```markdown
추가 설명이 필요한 문장입니다.[^memo]

[^memo]: 여기에 보충 설명을 작성합니다.
```

### 접기와 펼치기

HTML을 지원하는 환경에서 사용하는 예제다. HTML 내부의 마크다운 처리 방식은 환경별로 다를 수 있다.

```html
<details>
<summary>보충 설명 열기</summary>

여기에 자세한 내용을 적습니다.

</details>
```

### 수식

인라인 수식은 `$...$`, 별도 블록 수식은 `$$...$$`로 감싼다.

```markdown
직각삼각형의 관계: $a^2 + b^2 = c^2$

$$
E = mc^2
$$
```

## 15. 플랫폼별 차이와 옵시디언 문법

원문은 기본 마크다운, GitHub, 옵시디언, Notion의 차이를 비교한다. 핵심은 **같은 텍스트도 앱의 확장 기능과 입력 방식에 따라 다르게 처리될 수 있다**는 점이다. 원문의 지원 여부 표는 버전과 입력 방식에 영향을 받으므로, 여기서는 일괄적인 지원 판정 대신 옵시디언 활용 문법을 정리한다.

```markdown
[[학습 노트]]
[[학습 노트|수업 정리]]
[[학습 노트#핵심 개념]]

![[학습 노트]]
![[play.png|400]]

#학습
==다시 볼 내용==
```

위 예제는 순서대로 노트 연결, 표시 이름 변경, 제목으로 연결, 노트 삽입, 이미지 너비 지정, 태그, 하이라이트다.

## 16. 빠른 참조와 실수 방지

| 하고 싶은 일 | 기억할 문법 |
| --- | --- |
| 제목 만들기 | `## 제목` |
| 강조하기 | `**내용**` |
| 할 일 기록 | `- [ ] 작업` |
| 링크 연결 | `[이름](주소)` |
| 이미지 표시 | `![설명](경로)` |
| 인용하기 | `> 내용` |
| 노트 연결 | `[[노트 이름]]` |
| 중요한 부분 표시 | `==내용==` |

자주 확인할 사항:

- 제목 기호 뒤에 공백을 넣었는가?
- 수평선 앞뒤에 빈 줄이 있는가?
- 문단 구분과 줄바꿈을 구별했는가?
- 파일명과 문법 기호를 그대로 보여줘야 한다면 코드로 감쌌는가?
- 표의 제목 행 아래에 구분 행이 있는가?
- 코드 블록의 닫는 백틱을 빠뜨리지 않았는가?
