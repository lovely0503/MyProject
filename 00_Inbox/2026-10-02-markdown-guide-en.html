Small symbols.
Well-structured notes.

Learn Markdown through 16 concise topics, reusable examples, and a focused introduction to Obsidian syntax.

Prepared October 2, 2026 · English adaptation of the Korean study summary

Source: Complete Markdown Guide — Yuhan University, Game Contents Major

01 / FUNDAMENTALSWhat is Markdown?

Markdown uses simple symbols to add structure and formatting to plain text. Files are commonly saved with the .md extension and used for notes, README files, and technical documentation.

The source remains readable and portable, but support for extended syntax varies between applications. This guide summarizes the source’s 16 topics and adapts its examples for practice.

02 / FUNDAMENTALSHeadings

Place a space after the # symbols. Use one to six symbols to create heading levels.

# Study notes
## Today's topic
### Key concept
#### Details
##### References
###### Additional notes

Underlined headings are another option: a line of === below text creates a level-one heading; --- creates a level-two heading.

03 / FUNDAMENTALSText emphasis

EffectSyntax
Bold**key point** or __key point__
Italic*emphasis* or _emphasis_
Bold and italic***important***
Strikethrough~~old content~~
Inline code`score`

Wrap filenames and commands in inline code to display their punctuation literally.

04 / FUNDAMENTALSParagraphs and line breaks

  • New paragraph: leave a blank line between blocks of text.
  • Line break within a paragraph: end a line with two spaces, then press Enter.
  • The display of an ordinary line break can depend on the editor’s settings.
This is the first paragraph.

This is the second paragraph.

05 / STRUCTURELists

Start an unordered item with -, *, or +. For ordered lists, use a number followed by a period. Indent child items.

- Game production
    - Planning
    - Development

1. Outline the idea
2. Build a prototype
3. Run a playtest

Repeating 1. for each ordered item can still produce consecutive numbers when rendered.

06 / STRUCTURELinks

[Course materials](https://example.com)
[Course materials](https://example.com "Open materials")

<https://example.com>
<student@example.com>

[Lecture notes][class]

[class]: https://example.com

Reference-style links keep the destination URL in a separate definition, making repeated links easier to maintain.

07 / STRUCTUREImages

Add ! before a link. Use alternative text to describe the information conveyed by the image.

![Gameplay screen](play.png)
![Gameplay screen](play.png "Test scene")
[![Resource banner](banner.png)](https://example.com)

![Gameplay screen][shot]

[shot]: play.png

In Obsidian, you can specify the image width:

![[play.png|300]]

Replace the example filenames with actual files in your vault. The examples above show syntax; they do not include image assets.

08 / STRUCTUREBlockquotes

Start a quote with >. Add more symbols for nested quotes. Emphasis and inline code also work inside a quote.

> Today's study note
>
> **Key point:** Start with a small example.
>> Something to investigate further

09 / STRUCTUREHorizontal rules

Put ---, ***, or ___ on its own line. Blank lines around the rule help avoid confusion with underlined headings.

First section

---

Second section

Do not append an explanatory sentence to the rule’s line: it may prevent the line from being recognized as a rule.

10 / ADVANCED BASICSCode

Use a pair of backticks for inline code and three backticks on separate lines for a code block. If the content contains backticks, use a longer outer delimiter.

Store the points in `score`.

```python
score = 80
print(score)
```

Show literal backticks: `` `score` ``

A language name after the opening fence, such as python, javascript, csharp, html, or json, enables language-specific highlighting where supported. Four-space indentation is another way to create a code block.

11 / ADVANCED BASICSTables

Separate columns with | and place a separator row below the header. Colons in that row control alignment.

| Task | Owner | Progress |
| :--- | :---: | ---: |
| Planning | Alex | 100% |
| Development | Sam | 60% |
  • :---: left aligned
  • :---:: centered
  • ---:: right aligned

Cells can contain emphasis, links, and inline code. Keep multiline code blocks outside the table.

12 / ADVANCED BASICSTask lists

Use - [ ] for an incomplete task and - [x] for a completed task. Keep the spaces inside and after the brackets where shown.

- [x] Read the study materials
- [ ] Complete the practice
    - [ ] Create a table
    - [ ] Insert an image

13 / ADVANCED BASICSEscaping characters

Place a backslash \ before a syntax character to display it literally.

\*Literal asterisks, not emphasis\*
\# A sentence, not a heading
\[Visible brackets\]
1\. A sentence, not a numbered list

Inline code is also useful for filenames and code containing many special characters.

14 / EXTENSIONSExtended features

The source introduces these features in its GitHub extensions section. Distinguish GFM syntax, such as tables and task lists, from additional features provided by individual services.

Footnotes

A sentence that needs more explanation.[^memo]

[^memo]: Add the supporting explanation here.

Collapsible content

This example requires an environment that supports the relevant HTML. Markdown processing inside HTML can vary.

<details>
<summary>Open additional explanation</summary>

Write the details here.

</details>

Mathematical expressions

Use $...$ for inline math and $$...$$ for a separate math block in supporting applications.

Right-triangle relationship: $a^2 + b^2 = c^2$

$$
E = mc^2
$$

15 / OBSIDIANPlatform differences and Obsidian syntax

The source compares basic Markdown, GitHub, Obsidian, and Notion. The main lesson: the same text can behave differently depending on an app’s extensions and input methods. Feature support can also change with versions, so this summary focuses on practical Obsidian syntax rather than a universal compatibility table.

[[Study notes]]
[[Study notes|Course summary]]
[[Study notes#Key concept]]

Before you finish

  • Add a space after heading markers.
  • Leave blank lines around horizontal rules.
  • Distinguish new paragraphs from line breaks.
  • Use inline code when filenames or syntax symbols should appear literally.
  • Include a separator row below table headers.
  • Close every fenced code block.
