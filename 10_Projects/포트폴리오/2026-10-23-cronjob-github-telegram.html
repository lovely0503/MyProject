01 / GOAL

반복하는 업로드를 작업으로 등록하기

옵시디언과 VS Code에서 사용하는 C:\kang의 새 파일을, 매시간 lovely0503/MyProject 저장소의 main 브랜치에 올립니다. 업로드 결과는 텔레그램의 @myproject_lovely0503_bot으로 받습니다.

이번 실습에서 말하는 ‘크론잡’정해진 주기로 실행하는 자동 작업이라는 의미입니다. 실제 구현은 Windows 작업 스케줄러입니다. Linux의 crontab을 등록한 것은 아니며, 작업 등록 1분 뒤 시작해 1시간 간격으로 반복하도록 구성했습니다.

02 / HOW IT WORKS

확인 → 비교 → 업로드 → 알림

  1. 01 / TRIGGER예약 실행Windows 작업 스케줄러가 PowerShell 실행
  2. 02 / COMPARE새 경로 확인로컬 파일과 GitHub 파일 목록 비교
  3. 03 / UPLOAD커밋 생성새 파일을 묶어 main 브랜치에 반영
  4. 04 / NOTIFY결과 전달텔레그램 전송과 로컬 로그 기록

GitHub CLI의 로그인 정보를 사용해 GitHub REST API를 호출합니다. 새 파일은 blob → tree → commit 순서로 생성하고, 브랜치 참조를 갱신합니다. 다른 작업이 먼저 반영되어 충돌하면 강제 덮어쓰기 대신 실패로 처리합니다.

03 / IMPLEMENTATION

오늘 연결한 세 가지

① GitHub 인증과 업로드

GitHub CLI의 기기 인증으로 lovely0503 계정에 연결했습니다. 쓰기 권한을 확인하고, 원격 경로가 없는 파일만 새 파일로 판단하도록 했습니다. 같은 경로의 파일 수정이나 삭제는 반영하지 않습니다.

② Windows 작업 스케줄러

업로드 스크립트를 호출하는 반복 작업을 등록했습니다. 실제 예약 작업을 한 번 실행해, 성공 종료 코드 0과 새 파일이 없을 때의 로그를 확인했습니다.

③ 텔레그램 봇

BotFather에서 알림봇을 만들고, 봇과 대화를 시작했습니다. PC의 설정 스크립트에 봇 토큰을 숨김 입력한 뒤, 수신할 개인 대화의 Chat ID를 선택했습니다. 연결 테스트 메시지는 텔레그램에서 수신 확인했습니다.

토큰과 Chat ID는 서로 다른 값입니다.봇 토큰은 숫자:문자열 전체이고, Chat ID는 알림을 받을 대화방의 숫자입니다. 토큰은 Windows DPAPI로 암호화해 현재 사용자·PC에 연결된 설정으로 저장합니다. 이 문서에는 토큰과 개인 Chat ID를 넣지 않았습니다.

구성 파일

  • .github-sync/Upload-NewFiles.ps1원격 목록 비교, 새 파일 업로드, 실행 결과 기록
  • .github-sync/Enable-HourlySync.ps1계정·쓰기 권한 확인 후 매시간 예약 작업 등록
  • .github-sync/Configure-Telegram.ps1토큰 숨김 입력, 대화 ID 선택, 테스트 메시지 전송, 암호화 설정 저장
  • .github-sync/Telegram-Notify.ps1저장된 설정을 사용해 Telegram Bot API 호출
  • .github-sync/sync.log업로드, 새 파일 없음, 오류 등을 기록하는 로그
  • .github-sync/telegram.xml암호화된 봇 인증 설정 · 자동 업로드 대상에서 제외

성공 메시지 형식 예시

알림 때문에 업로드 결과가 뒤바뀌지 않도록

업로드가 성공했는데 텔레그램 전송만 실패하면, 업로드는 성공으로 유지하고 로그에 알림 실패 경고를 남깁니다. GitHub 반영 후 로컬 기록에 문제가 생긴 경우에도 업로드 성공 사실과 로컬 기록 오류를 구분하도록 구성했습니다.

06 / OPERATIONS

직접 확인하고 관리하는 명령어

VS Code의 PowerShell 터미널에서 실행합니다. 아래 명령은 로컬 스크립트가 있는 PC 기준입니다.

새 파일 목록만 미리 보기

POWERSHELL / DRY RUN
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\kang\.github-sync\Upload-NewFiles.ps1" -DryRun

지금 업로드하기

새 파일이 있으면 실제로 GitHub에 올리고 텔레그램으로 결과를 보냅니다.

POWERSHELL / UPLOAD
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\kang\.github-sync\Upload-NewFiles.ps1"

최근 기록과 예약 상태 확인

POWERSHELL / STATUS
Get-Content "C:\kang\.github-sync\sync.log" -Tail 20
Get-ScheduledTask -TaskName "MyProject-Hourly-New-Files"
Get-ScheduledTaskInfo -TaskName "MyProject-Hourly-New-Files"

자동 실행 중지 · 다시 시작

POWERSHELL / SCHEDULE
# 중지
Disable-ScheduledTask -TaskName "MyProject-Hourly-New-Files"

# 다시 시작
Enable-ScheduledTask -TaskName "MyProject-Hourly-New-Files"

07 / SCOPE & NEXT STEPS

지금 되는 것과, 다음에 할 것

  • 업로드 범위: 루트의 지원 문서·웹 파일과 00_Inbox, 10_Projects, 20_Areas, 30_Resources, 40_Archive 아래 지원 확장자의 새 파일을 확인합니다.
  • 변경 처리: 같은 경로가 GitHub에 있으면 건너뜁니다. 기존 파일의 수정·삭제를 반영하는 양방향 동기화 기능은 없습니다.
  • 제외 항목: 점으로 시작하는 경로, 의존성·빌드 폴더, 특정 민감정보 관련 파일명, 20MiB 초과 파일 등을 제외합니다. 파일 내용 자체에 대한 비밀정보 검사는 하지 않습니다.
  • 알림 범위: 이 업로드 스크립트의 실행 결과를 보냅니다. GitHub 웹사이트나 다른 도구에서 직접 업로드한 결과는 감지하지 않습니다.
  • 연결 조건: PC 전원, 사용자 로그인, 인터넷이 필요합니다. 인터넷이 완전히 끊기면 실패 알림도 전달되지 않을 수 있습니다.
  • 검증 범위: ‘업로드 성공’은 GitHub에 파일이 반영됐다는 뜻입니다. 프로그램이 정상 동작하거나 테스트를 통과했다는 뜻은 아닙니다.

다음 확장 방향

프로그램의 언어와 실행 방법을 정한 뒤 GitHub Actions에 빌드·테스트를 연결하고, 그 결과도 텔레그램으로 보낼 수 있습니다. 기존 파일 수정 반영과 알림 재전송 정책은 별도의 요구사항으로 정해 추가할 수 있습니다.
