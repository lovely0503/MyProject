# CLI란 무엇인가

> CLI는 명령어를 입력해서 프로그램을 사용하는 방식이다. 버튼을 클릭하는 대신, 하고 싶은 작업을 글자로 입력한다.

## CLI와 GUI

**CLI**는 **Command Line Interface**의 약자다. 한국어로는 ‘명령줄 인터페이스’라고 한다.

반면 창, 버튼, 메뉴 같은 화면 요소를 클릭하는 방식은 **GUI(Graphical User Interface)**라고 한다.

| 구분 | 사용하는 방법 | 예시 |
| --- | --- | --- |
| GUI | 화면의 버튼과 메뉴를 클릭한다. | GitHub 웹사이트에서 파일 업로드 버튼 누르기 |
| CLI | 명령어를 입력한다. | GitHub CLI로 업로드 작업 요청하기 |

둘 다 프로그램을 사용하는 방법이다. 같은 작업을 GUI와 CLI 양쪽에서 지원하는 경우도 있다.

## 터미널·PowerShell·CLI는 어떻게 다를까?

| 용어 | 의미 | 내 환경에서의 예 |
| --- | --- | --- |
| 터미널 | 명령어를 입력하고 결과를 보는 창 | VS Code 아래쪽의 터미널 패널 |
| 셸(Shell) | 입력한 명령을 해석하고 실행하는 프로그램 | PowerShell |
| CLI | 명령줄로 프로그램을 사용하는 인터페이스 | GitHub CLI, Vercel CLI |

**터미널은 창, PowerShell은 그 안에서 명령을 처리하는 프로그램, CLI는 글자로 프로그램을 조작하는 방식**으로 이해하면 쉽다.

## `PS C:\kang>`은 무슨 뜻일까?

```text
PS C:\kang>
```

- `PS`: PowerShell을 사용 중이라는 표시다.
- `C:\kang`: 현재 작업 중인 폴더다.
- `>`: 이 뒤에 명령어를 입력하면 된다는 표시다.

이것은 오류 메시지가 아니라, 명령어를 기다리고 있다는 뜻이다. 명령어를 복사할 때는 `PS C:\kang>`까지 복사할 필요가 없다.

예를 들어 다음 명령은 현재 폴더 위치를 확인한다.

```powershell
Get-Location
```

다음 명령은 현재 폴더 안의 파일과 폴더 목록을 보여준다.

```powershell
Get-ChildItem
```

## 이번 AX 작업에서 사용한 CLI

| 도구 | 맡았던 일 |
| --- | --- |
| GitHub CLI (`gh`) | GitHub 계정 인증과 저장소 API 호출 |
| Vercel CLI (`vercel`) | Vercel 계정 인증, 프로젝트 연결, 포트폴리오 배포 |
| PowerShell | 업로드·알림·설정 스크립트 실행 |

이번 작업에서는 일부 도구를 전용 폴더에 설치했으므로, 터미널에 `gh`나 `vercel`만 입력하면 인식되지 않을 수 있다. 설치된 도구의 전체 경로나 준비된 스크립트를 사용해 실행할 수 있다.

## 명령어와 입력값은 구분하기

PowerShell이 명령어를 기다릴 때 텔레그램 봇 이름을 입력하면, 그 이름을 실행할 프로그램으로 해석한다. 실제 명령어가 아니므로 ‘인식되지 않습니다’라는 오류가 발생한다.

반면 설정 스크립트가 실행된 뒤 `Telegram bot token:`이나 `Chat ID:`를 물어보면, 그때는 해당 스크립트에 값을 입력하는 단계다. 봇 토큰은 명령어 자체가 아니라 인증을 위한 비밀 입력값이다.

## CLI를 사용하는 이유

- 같은 작업을 명령어로 반복하기 쉽다.
- 여러 명령을 스크립트로 묶어 자동화할 수 있다.
- 실행 결과를 로그로 남기고 오류를 확인하기 좋다.
- 작업 스케줄러와 연결해 정해진 시간마다 실행할 수 있다.

우리가 만든 매시간 GitHub 업로드도, 작업 스케줄러가 PowerShell을 실행하고 스크립트가 필요한 기능을 호출하도록 구성한 자동화 사례다. CLI 자체가 예약 시간을 관리하는 것은 아니다.

## 한 문장 정리

**CLI는 글자로 명령을 내려 프로그램을 사용하는 방식이며, 반복 작업을 스크립트와 자동화로 연결할 때 유용하다.**
